RPi 主系統與 LCD 子系統板
資料串接方案評估

版本：草案 v0.1　｜　日期：2026-11-12　｜　討論範圍：方案一、方案二

1. 背景

本產品為光固化 3D 列印機。主系統（RPi 4 / RPi 5）由貴司開發，Phrozen 負責子系統板：接收切片圖、驅動 LCD 及控制 UV LED。

USB 角色限制：貴司希望以 USB 2.0 串接。經原廠確認，SSD202D 的 USB 控制器僅支援 Host，無法改為 Device，因此無法直接作為 RPi USB Host 埠的周邊裝置。以下兩個方案為因應此限制而提出。

2. 方案一：RPi 以 SPI 直連 FPGA

移除 SoC，RPi 直接以 SPI 送圖給 FPGA，並沿用既有的 FPGA 指令控制 LCD。

2.1 目前進度（Phrozen）

項目狀態說明
沿用既有 FPGA 的 LCD 控制指令可沿用現有功能
子系統板硬體修改（測試用跳線）確認中與硬體同仁確認中，目前尚無測試板
RPi → FPGA 實際傳輸速度待測試目前 6～12 MB/s 為估計值
光機／UV LED 等額外控制待評估可能需修改 FPGA，本次暫不討論

2.2 貴司需配合的改動

類別內容
硬體
  • 量產需設計轉接板將 SPI 引出（測試階段可用跳線，量產不可）
  • 確認 RPi GPIO 目前占用狀況：SPI0（GPIO 7～11）之外，建議另保留 1～2 支 GPIO 作為 busy／ready 或中斷（SPI 本身無流量控制）
  • 控制線長與接頭品質，SPI 跨板在高時脈下易受訊號完整性影響
軟體
  • 使用 spidev 驅動，需調大 spidev.bufsiz（預設每次僅 4 KB）
  • 實作雙方議定之傳輸協定（含 ack／CRC 錯誤檢查）
系統分工原由 SoC 負責的控制功能，需改由主系統或 FPGA 承接（待討論）

3. 方案二：RPi USB Gadget 串接 SoC

保留現有子系統架構。RPi 的 Type-C 埠切換為 USB Device（Gadget）模式，接到 SSD202D 的 USB Host（Type-A）埠。

3.1 目前進度（Phrozen）

項目狀態說明
RPi 4 Type-C 切換為 Gadget 模式已驗證功能正常
RPi 4 ↔ PC 傳輸速度（g_serial）已實測約 12 MB/s，視為目前下限
改用 FunctionFS（USB bulk）提升速度待評估g_serial 經 tty 層，額外負擔較大，預期可再提升
RPi 5 Gadget 模式待驗證預期可行
RPi ↔ SoC 實際對接進行中SoC 端需修改 kernel

3.2 貴司需配合的改動

類別內容
軟體
  • config.txt 加入 dtoverlay=dwc2,dr_mode=peripheral，並載入 Gadget 模組
  • 傳圖程式改由 Gadget 端送出資料
電源
  • Type-C 原為 RPi 電源輸入，改為資料用途後，建議使用 Y cable 將電源與資料分開：
    • 電源分支：VBUS、GND、CC（Type-C 電源須偵測到 RPi 的 CC 下拉電阻才會輸出；RPi 5 亦透過 CC 進行 PD 協商）
    • 資料分支：D+、D−、GND
  • 不建議由 GPIO 5V 供電：此路徑未經過 RPi 的電源保護電路；除非貴司電源板已自帶保護
  • RPi 5：若電源未經 PD 協商出 5V/5A，USB 輸出會被限制在 600 mA。需使用支援 PD 的 Y cable，或於 config.txt 設定 usb_max_current_enable=1
Phrozen 端對應：為避免 SoC Host 輸出的 5V 與 RPi 電源互相回灌，子系統板將移除 USB 埠的 VBUS 輸出（保留 0Ω 電阻，日後可切換回一般 Host 用途，例如韌體更新）。因此無論 Y cable 資料端是否帶 VBUS，皆不影響使用。

4. 方案比較

項目方案一：SPI 直連 FPGA方案二：USB Gadget 接 SoC
傳輸速度估計 6～12 MB/s（待實測）RPi 4 ↔ PC 實測約 12 MB/s；整體速度另受 SoC → FPGA 段限制
驗證進度尚無測試板RPi 端已驗證；與 SoC 對接進行中
子系統架構移除 SoC，架構精簡維持現有架構
貴司硬體改動SPI 轉接板、GPIO 規劃電源與資料分離（Y cable，電源端需含 CC）
貴司軟體改動spidev 驅動＋傳輸協定Gadget 設定＋傳圖程式
主要風險SPI 跨板訊號完整性；原 SoC 功能需重新分工電源設計；RPi 5 供電限制

5. 請貴司協助提供的資訊

  • 量產機型為 RPi 4、RPi 5，或兩者皆需支援？
  • RPi GPIO 目前占用狀況（方案一需要）
  • 電源架構：使用 RPi 原廠電源，或貴司自製電源板？是否有保護電路？
  • 每層的目標列印週期（秒）：將決定是否必須導入壓縮與雙緩衝
