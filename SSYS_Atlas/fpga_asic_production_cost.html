02起因

西柏反映 FPGA 報價太貴。

奔馳的結論：目前 FPGA 是驗證期間使用，量產建議改用 TV / monitor ASIC。

03基本觀念釐清

FPGA

  • 可重新定義內部電路的晶片，適合開發與驗證（原型）
  • PL（Programmable Logic）：可程式化硬體，燒不同 bitstream 變不同電路
  • PS（Processing System）：晶片內固定的 ARM 處理器，硬體不可改，只能換上面跑的軟體
  • 驗證完的核心板可留作下一個專案的開發平台

ASIC

  • 為特定用途做死的晶片，功能固定，量產單價低、功耗低
  • 客製 ASIC 開發費（NRE）極高，量不大不划算
  • 奔馳所指應是「現成的顯示控制晶片」（ASSP，如 scaler / T-con 類） 需向奔馳確認

XCZU1CG 已是最便宜的型號

  • Zynq UltraScale+ 家族最便宜的一顆，同家族內往下換沒有空間
  • 唯一不改程式的省錢方式：確認是否用了過高的速度等級或溫度等級（全系統為商規 0–70°C，E-grade 即可）

04換晶片後，之前的開發還有用嗎？

✓ 會留下來的（換晶片的基礎）

  • 系統規格：面板驅動時序、bias 電壓、上下電順序
  • USB 通訊協定：0xA7 重置、FIFO、checksum 等定義
  • 影像格式與頻寬需求（3-bit 改 6-bit，每張約 75 MB）
  • 整機架構與踩過的坑

✗ 需要重做的

  • FPGA PL 邏輯（Verilog / VHDL）無法直接搬到現成晶片
  • PS 端軟體需依新晶片 SDK 大幅改寫
  • 供電板需配合新晶片電壓重新設計
結論：程式碼大多不能直接沿用，但驗證出的規格是 ASIC 選型的必要依據。（詳見 延伸問答 Q2）

05供電板的定位

  • 目前西柏做的供電板 = prototype，僅供驗證（proto 10 片）
  • 量產換 ASIC 後需重做，但非從零開始

需改的（與 FPGA 綁定）

  • 六條 logic rails（0.85 V / 1.1 V / 1.2 V / 1.8 V / 3.3 V / 5 V）
  • FPGA 上下電時序、PS_POR gating
  • J1 核心板接口（量產可能改為單板設計）

可沿用的（與 FPGA 無關）

  • 輸入級：12–24 V、Micro-Fit、fuse、反接保護、SMBJ30A TVS、soft-start（inrush < 3.5 A）
  • 前級 5 V 降壓（TPS54360）
  • 面板 bias：±6.2 V、1.8 V VDDIO、開關順序、0xA7 受控放電
  • USB 實體介面、接地 / EMC 做法、風扇電源
建議：告知西柏本板定位為驗證用，以功能正確、好量測除錯為優先，不必投入量產成本優化或 DFM。

06西柏針對 ASIC 評估提出的五個問題

Q1除 MIPI 外，還有哪些必需介面？（UART、I2C 這個我們了解）
介面說明
MIPI DSI雙 port × 4 lane 同步輸出，RGB666 packed，13 Hz；每 lane 約 1 Gbps；需支援 LP 模式送 init 指令（見 延伸問答 Q3）
USB 2.0 HS Device收圖與指令，約 30–40 MB/s
UART / I2CUART0、UART1、I2C1
SWD / JTAG除錯
GPIO面板 RESETB、TE、BIST、PANEL_ID、面板電源開關控制
風扇 PWM
開機儲存SPI Flash 或 eMMC
關鍵：外部記憶體 1 GB 為佳
一張圖片約 75 MB；13 Hz 持續刷新需約 1 GB/s，介面理論頻寬建議 2 GB/s 以上。
Q2如何控制整台機台？是有按鍵板？
  • 本板不負責整機控制，角色為「顯示控制器」
  • 馬達 / 加熱器等由既有主板（IOB）控制
  • Raspberry Pi 透過 USB 送圖
  • 按鍵 / 觸控 UI 文件未提及，推測在 Pi 或主板側
Q3PC 傳圖至板子是透過 USB 2.0？（方塊圖 J3）
  • 是 USB 2.0 High-Speed，但送圖端是 Raspberry Pi，不是 PC
  • FPGA = USB Device，Pi = Host（已與客戶簽核）
  • J3 為核心板接點，對外 USB 接頭在供電板 J11
  • 方塊圖 J8（接 CP2102N）是 USB 轉 UART 除錯用，與傳圖無關
  • USB 2.0 實際約 30–40 MB/s，6-bit 一張約需 2 秒
Q4Ethernet 的功能是網頁控制頁面？

LCD 驅動不需要用到 Ethernet。

Q5LCD 一定要 MIPI 還是也可用 LVDS？
  • ZE170DA-01A 只有 MIPI（port A + port B，各 4 lane），無 LVDS 腳位
  • 介面由面板 driver IC 決定，板端無法改
  • 若要 LVDS：(a) 問群創有無 LVDS 版本；(b) 加 LVDS 轉 MIPI 橋接晶片（此解析度與雙 port 配置是否有現成晶片支援，需另查）
  • 其他三種面板（7.1" / 10" / 13.5"）介面
這是 ASIC 選型最大關卡：一般 TV / monitor 晶片輸出多為 LVDS、V-by-One、eDP，MIPI DSI 輸出較常見於手機 / 平板處理器；且本面板為雙 port、非標準解析度、低幀率灰階，現成晶片可能不多。

07延伸問答

Q1如果換成別的 FPGA IC（也同樣帶有 PS、PL 的），原有的程式可以沿用嗎？

要看換成哪一顆。同家族內換型號，大部分可以沿用；跨家族或換廠牌，程式邏輯可以參考，但實際上要移植甚至重寫，而且供電板也得跟著改。

XCZU1CG 已經是 Zynq UltraScale+ MPSoC 家族裡最小、最便宜的一顆，想在同家族內往下換更便宜的型號，基本上沒有空間。要明顯降成本，通常得換到別的家族或別的廠牌，而這正是程式沿用難度最高的情況。

三種換法，沿用程度差很多：

換法例子PS 端軟體PL 端設計供電板
同顆換等級／封裝ZU1CG 不同速度等級或溫度等級幾乎全部沿用重新合成、檢查 timing 即可大致不變
同廠牌不同家族AMD Zynq-7000（XC7Z010／7Z020）需移植RTL 可沿用，IP 與腳位要重做要重新設計
換廠牌Intel/Altera SoC、Microchip PolarFire SoC 等大幅改寫廠牌專屬 IP 全部重做要重新設計
Q2開發廠商說「建議找 TV / monitor ASIC 取代 FPGA，目前這個 FPGA 是驗證期間用」，換成 ASIC 那之前開發的是不是就沒用了？

FPGA 在這裡扮演的是原型角色。很多產品都是先用 FPGA 把功能做出來、驗證「這樣到底行不行」，確認沒問題後再換成便宜的晶片量產。如果一開始就直接挑 ASIC，萬一需求沒想清楚或面板驅動有問題，晶片選錯就很難回頭。

具體來說，這段驗證期留下來的東西包括：

會留下來的

系統規格（面板驅動時序、bias 電壓、上下電順序）、USB 通訊協定（包含 0xA7 重置、FIFO、checksum 這些定義）、影像資料格式與頻寬需求（3-bit 改 6-bit、每張 75 MB 這種數字）、整機架構和踩過的坑。這些是之後挑 ASIC 時最重要的「規格書」，沒有它們根本不知道該選哪顆。

要重做的

FPGA 的 PL 邏輯（Verilog / VHDL）不會直接搬到現成晶片上，因為現成晶片的功能是固定的，只能用它提供的設定或韌體介面。PS 端的程式可能部分可參考，但大多要依新晶片的 SDK 改寫。供電板也會跟著改，因為新晶片需要的電壓組合會不同。
所以比較準確的說法是：程式碼本身大多不能直接用，但它證明出來的東西是換晶片的基礎。
Q3「LP 模式送 init 指令」——LP 模式是什麼？

LP 是 Low Power（低功耗）模式，是 MIPI 的兩種傳輸模式之一。MIPI 的同一組線，會在兩種模式之間切換：

模式特性本案用途
LP（Low Power）低速、低功耗送 initial code（面板設定指令）、sleep in 等控制指令
HS（High Speed）高速差動傳輸送影像（Video Packet）

用在哪裡

對照群創規格書 4.2 節的上電時序圖，順序是這樣：

  1. 面板上電後，MIPI 線先停在 LP-11（LP 模式下的閒置狀態）
  2. 主控用 LP 模式送 initial code，也就是「REGW」那串——一連串寫入面板 driver IC 暫存器的指令，告訴它解析度、時序、格式等設定
  3. 設定完成後，切到 HS 模式開始送影像（Video Packet）

關機時則送 sleep in 指令，最後進入 ULPM（Ultra-Low Power Mode，超低功耗待機）。

類比：很像 MCU 開機時先用慢速的 I²C 把感測器的暫存器設定好，之後再開高速通道大量傳資料。差別在於 MIPI 是同一組線切換兩種模式，不是兩組不同的線。

為什麼要特別列在規格裡

有些晶片的 DSI 輸出只擅長送 HS 影像，送指令的功能很陽春，或只能用 HS 模式送指令。如果面板 driver IC 要求 init code 用 LP 送，而晶片做不到，面板就初始化不起來、根本不會亮。

另外規格書 4.2 節下方有一行備註，建議送 initial code 前先送 8 個 HS clock 來抑制電源或地雜訊。這種細節也要晶片的 DSI 控制器夠彈性才做得到。
